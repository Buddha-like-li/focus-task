# Windows 客户端垃圾桶界面

## 用户目标与范围

- 用户目标：普通删除后的任务进入垃圾桶；用户可恢复，或在明确的中文二次确认后彻底删除。
- 彻底删除的用户可见范围：服务端负责删除任务记录、附件、任务文档、快照和服务端报告副本；客户端在服务端成功后清理 `Documents\Focus Task\Reports` 内该任务的应用托管 Markdown 副本。
- 本任务只覆盖 Windows 客户端的 API 接入、垃圾桶状态、导航、确认交互和受控本机副本清理。不得修改服务端、Docker、服务凭证、发布配置或数据卷。

## 实现设计

- 普通删除仍调用兼容的 `DELETE /api/tasks/{id}`，但客户端全部可见入口均称为“移入垃圾桶”。已完成任务的批量移动先经中文确认；部分失败时显示成功数和失败数，绝不静默。
- 新增独立 `trashStore`，仅使用垃圾桶接口，不复用工作台的已删除任务缓存。账户切换、退出和登录失效时清空垃圾桶状态并废弃旧请求响应。
- 垃圾桶页面不渲染任务详情、附件下载、文档预览或打开文件夹入口，避免已删除任务绕过服务状态。
- 恢复成功后重新拉取工作台任务；永久删除成功后立即从垃圾桶和工作台内存缓存中移除。
- 永久删除使用页面内受控中文对话框，明确不可恢复、子任务会一并处理，并在处理期间禁用取消、关闭和重复确认。服务端返回 401、403、404、409 时转换为可读中文提示；尤其 409 会说明任务可能与已有任务冲突或不满足本机安全限制。
- 永久删除响应的 `cleanup_pending=true` 表示服务记录已删除、服务端文件清理待处理。客户端保持任务从垃圾桶移除，但显示“服务记录已删除，文件清理待处理”，不得误报为全部清理完成。

## 本机报告副本清理边界

- Tauri 命令只接受正整数任务 ID，绝不接受目录、文件名或任意路径参数。
- 命令固定枚举 `Documents\Focus Task\Reports` 的直接子项；仅删除普通文件，拒绝符号链接且不递归进入目录。
- 仅严格匹配 `task-<任务ID>-<字母数字或连字符时间标记>.md` 的应用托管任务 Markdown 副本。相同目录中的其他任务、汇总报告、非 Markdown 文件和子目录均保留。
- 同一受控文件名被用户手工编辑时仍属于该任务副本，按本次用户明确授权删除；用户另存到其他位置的文件不在范围内。
- 本机副本清理只会在服务端永久删除成功后触发。清理失败不会伪造服务端回滚，客户端显示“服务数据已删除，但本机报告副本清理失败”。

## 风险与门禁

- 已检查 `docs/code-audit-2026-07-21.md`：旧桌面数据迁移 P0 不由本任务处理；客户端不读取、迁移、备份或删除旧安装目录的数据。
- 客户端/服务 API 契约是 P1 门禁。服务端必须独立实现、审核并在本机服务容器中联调，确认当前账号隔离、父子任务、409 冲突、服务端关联清理和 local-only 约束。
- 本任务不创建 Release、不修改版本号、不打 tag、不推送远程。正式发布仍需独立审核、集成人合入、完整 Windows 构建与发布门禁。
