# 任务提醒规则修复

## 用户目标与范围

- 用户目标：自己创建的任务即使开始时间和截止时间设为当天，也不应立即弹出开始提醒、截止提醒和过期提醒；转交给他人的任务仍应提醒接收人；任务逾期从截止日期的次日开始计算。
- 本任务只修改 Windows 客户端提醒判断、逾期日期判断和对应前端测试。
- 不修改本地服务 API、服务镜像、容器、数据库、用户任务数据、认证、版本号、发布配置或远程仓库。

## 诊断与设计

- 旧提醒逻辑只判断目标时间减去提前提醒时间是否已经早于当前时间；新建任务只要开始或截止时间落在过去几分钟或过去几个小时，就会在下一次轮询中立即补发提醒。
- 旧逾期逻辑按精确截止时间加 1 分钟计算；如果任务截止日期是今天但具体时间已经过去，就会在当天显示“已过期”。
- 服务端转交任务会写入 `previousOwnerId`；当前账号收到别人转交的任务时该字段非空，自建任务保持为空。因此客户端以该字段作为“是否属于转交接收任务”的现有运行时证据。
- 开始提醒和截止提醒仅对 `previousOwnerId` 非空的转交接收任务生效；自建任务即便保留旧字段默认值，也不会弹开始或截止提醒。
- 逾期判断改为本地日历日边界：截止日期当天不逾期，从截止日期的次日 0 点起才算逾期。该规则同时影响桌面通知和任务卡片逾期样式。
