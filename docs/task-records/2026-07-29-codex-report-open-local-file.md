# 任务文档自动保存并定位

## 用户目标与范围

- 用户反馈本地创建的任务点击文件夹图标后提示“请先下载后重试”。用户期望本地和远程任务均可直接打开任务文档所在文件夹。
- 本任务将文件夹操作改为先把当前任务 Markdown 写入受控 Windows 文档目录，再在资源管理器中定位该文件。
- 不读取旧安装目录、不访问容器内导出路径、不改服务 API、不改任务数据或下载资产。

## 风险与门禁

- 旧桌面数据兼容 P0 不受影响：本功能只写入用户主动请求的 `Documents\\Focus Task\\Reports` 文件，不读取、迁移、覆盖或删除旧任务数据。
- 客户端/服务 API 契约 P1 不受影响：继续使用现有 Markdown 快照字段，不新增或修改接口。
- 文件名继续由客户端生成并由 Tauri 端二次校验，服务端返回的容器路径不会传给本机文件操作。

## 实施、审核与验证

### 实施

- 文件夹按钮改为“保存并打开任务文档所在文件夹”。桌面端调用既有受控 Tauri 命令，将当前 Markdown 写入 `Documents\\Focus Task\\Reports` 后再由资源管理器定位；浏览器端继续使用普通下载回退。
- 不再要求用户先点击下载，也不再把服务端导出路径或容器路径传给本机文件操作。
- 更新视图测试，覆盖下载与“保存并打开”均只使用任务快照内容、不泄露服务端导出路径。
