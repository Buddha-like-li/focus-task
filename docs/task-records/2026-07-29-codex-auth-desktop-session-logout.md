# 桌面端会话持久化与退出切换账号

## 用户目标与范围

- 用户目标：Windows 桌面端登录一次后，在服务令牌有效期内再次启动无需重新输入密码；用户可明确退出当前账号并登录其他账号。
- 退出或切换账号后，不应继续显示前一账号的任务、需求池或团队数据。
- 本任务仅修改 Windows 客户端的认证会话、凭据管理器调用、账号状态清理和设置页账号操作。
- 不修改服务 API、Docker、数据卷、用户任务、发布配置、签名密钥或测试账号密码。
- 不保存明文密码。桌面端仅安全保存服务签发的 JWT 和用户名；浏览器开发模式维持既有 localStorage 行为。

## 实施内容

- 平台识别改为 Tauri 官方 `isTauri()`，确保桌面端进入原生凭据管理器路径，而不是误用 WebView 的浏览器存储。
- 保存会话后由原生端回读校验；任一凭据写入或校验失败时清除可能残留的两项凭据，避免半保存状态。
- 凭据管理器的读取、写入和清除失败均写入 `frontend.log`，并向用户展示中文可操作错误；日志不记录 JWT 或密码。
- 设置页新增“当前登录”账号区与“退出登录”操作。手动退出会先清除原生凭据，若失败则保留当前会话并告知用户，避免界面显示已退出而重启后旧账号恢复。
- 令牌被服务拒绝时采用独立的自动失效路径：即使凭据清理失败，也会清空 UI 会话并回到登录页。
- 退出时清空任务、需求池和团队的账号级内存状态，防止切换账号后短暂展示前一账号内容。

## 审核修订

- P1：任务、需求池和团队的加载请求使用会话版本号。退出清理会递增版本；请求开始时捕获版本，旧账号的响应、错误和 finally 均不能在新账号会话中回写数据、错误或加载状态。
- P1：Windows 凭据从两个独立记录收敛为一个序列化的 `auth_state` 记录，新写入会回读校验。读取继续兼容旧 `auth_token` 与 `auth_username`，退出同时清理旧记录。
- P1：退出清理先尝试两个旧记录；只有旧记录完整清除后才删除新的原子记录。若旧记录删除失败，新记录保留并优先于旧记录读取，避免下次启动回退并复活旧账号。
- P1：凭据管理器读取失败不再伪装为普通登出。客户端仅记录原生错误到日志，登录页只显示固定中文恢复提示；仍不回退到 WebView token 存储。登录/注册接口不读取旧 bearer token，用户可直接重新登录恢复。
- P2：登录接口得到新 token 后若立即被本地服务拒绝，会清空会话并向登录页抛出中文验证失败提示，不再无错误地跳转到受保护页面。

## 后续 P1 修订

- API 请求在发起前捕获令牌和会话版本。旧账号请求延迟返回 401/403 时，只会尝试失效与其令牌和版本都一致的当前会话，不能退出后来登录的其他账号。
- 任务、需求池、团队以及队友任务视图的异步请求都绑定账号级会话版本。退出或切换账号后，旧账号的新增、修改、删除、排序、成员操作、响应、错误和加载结束均不能回写新账号状态。
- 凭据保存后的回读失败采用独立清理顺序：先删除新的原子 `auth_state`，再尽力清理两个旧记录。即使旧记录删除报错，也不会留下会在下次启动时恢复的失败登录状态；手动退出保留原有的“旧记录未完整清除时保留当前原子状态”语义。
- 新增回归测试覆盖旧账号延迟 401、任务/需求/团队写操作隔离、队友任务视图隔离，以及上述原生凭据清理顺序。
- 原生凭据保存采用同一记录的“待确认→已提交”协议。旧格式（没有状态标记）继续按已提交读取；写入后的确认失败时，残留记录始终带待确认标记，加载端拒绝它且不回退旧凭据。第二次 `set_password` 成功即为提交，不再在已提交记录之后产生会让前端误判保存失败的回读步骤。
- 新增原生回归测试模拟：待确认记录写入成功、回读失败、删除 `auth_state` 失败、应用重启。验证加载端拒绝该次新令牌，且不会回退到旧凭据。

## 审计与风险边界

- 已阅读 `docs/code-audit-2026-07-21.md`。本任务不改变远端同步令牌、服务器地址切换、迁移或发布链路；其中远端同步认证边界不属于本次改动范围。
- 当前本地服务 JWT 有效期由服务环境变量控制，当前部署为 7 天。到期后需要重新登录，这是安全边界而不是桌面端重复索要密码。
- Windows Credential Manager 不可用时，首次登录或手动退出会提供可读错误；自动令牌失效仍会使客户端回到登录页。
