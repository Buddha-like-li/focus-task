# 任务归属交互恢复

## 目标与范围

- 用户目标：任务详情中的任务归属必须显示当前已保存值；用户可以输入并保存新的归属；历史任务归属必须可以明确看见并再次选择。
- 本任务只修改 Windows 客户端的任务详情控件与组件测试。
- 不修改本地服务 API、服务镜像、容器、数据库、用户数据、认证、版本号、发布配置或远程仓库。

## 诊断与设计

- 已只读核对本机服务 OpenAPI：既有 `TaskOut` 和 `TaskUpdate` 均支持 `task_belonging`，客户端既有请求转换继续将 `taskBelonging` 发送为该字段，本任务不改变契约。
- 本机数据卷的只读统计显示历史归属并未全局丢失；问题在 Windows WebView 中的 `input` 与 `datalist` 组合无法稳定呈现可输入和可见建议的交互。
- 将不稳定的 `datalist` 替换为两个明确控件：当前归属的文本输入框及保存按钮，以及展示常用和历史归属的原生选择框。
- 输入框使用独立草稿状态，切换任务时回显当前已保存值；可通过保存按钮、回车或失焦保存自定义文本。成功后新值立即成为建议；失败时恢复已保存值并沿用既有中文错误反馈。
- 历史建议从当前服务列表中的全部任务收集，包含已软删除任务，避免 `activeTasks` 过滤导致历史归属消失。

### 独立审核

- `/root/task_belonging_reviewer_v2` 独立审核首轮实现，结论为批准合入：未发现 P0/P1；组件测试 9/9、全量前端测试 87/87、生产构建和差异检查均通过。
- 审核记录一个 P2 交互边缘：输入框存在未保存文字时，点击历史选择框会先触发输入失焦保存，使选择框在保存期间禁用，部分 Windows WebView 可能需要再次点击。该问题不阻塞首轮批准，但必须在同一功能分支修复并复核。

### 修复复核

- `60f7460e7167c8e099ed77e81980729d8f744e16`：历史选择框的 `mousedown` 标记本次焦点切换；输入框由该点击引起的 `change`/`blur` 不再先保存草稿，随后选择框的 `change` 直接保存选中归属。新增事件顺序回归测试。
- `/root/task_belonging_reviewer_v2` 对修复独立复核后批准合入：无 P0/P1。确认抑制标志仅作用于由历史选择点击产生的输入 `change`/`blur`，不会影响保存按钮、回车或历史选择后的直接保存；定时器只保存组件局部状态，不读写任务或账号状态。
- P2：用户打开历史选择列表后取消选择时，该次输入失焦保存会被有意跳过，未保存草稿在随后切换任务时可能丢失。此行为避免了错误覆盖历史选择；若需要“任意失焦必保存”，应另立交互设计任务。
